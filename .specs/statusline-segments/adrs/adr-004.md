# ADR-004: Persist Cwd And Branch As statusLine Sibling Booleans

## Status

Accepted

## Date

2026-08-20

## Context

Existing optional segments persist through one path: `StatuslineItem`, `UserSettingsPatch.statusline_item`, `statusLine.<key>` in `~/.fx/settings.json`, catalog `SettingId`s, `/statusline <key>` toggles, and the compact picker. Project `.fx.json` already ignores profile-owned `statusLine`.

## Decision

Add `cwd` and `branch` as siblings of `sandbox`, `context`, and `session`. Extend `StatuslineItem`, parse/merge/source tracking, catalog choices, slash completions, help text, and shadow notices along that same path. Default both to off.

## Alternatives Considered

### Alternative 1: In-memory toggles only

- **Description**: Honor `/statusline cwd|branch` for the process without writing settings.json.
- **Pros**: Smaller persist surface.
- **Cons**: Breaks the existing toggle-and-persist contract and issue acceptance.
- **Why rejected**: Acceptance requires persist.

### Alternative 2: Nested identity object

- **Description**: Persist under `statusLine.identity.{cwd,branch}`.
- **Pros**: Groups future identity keys.
- **Cons**: Splits the persist and picker path for no current gain.
- **Why rejected**: YAGNI. Sibling booleans already match the store.

## Consequences

### Positive

- One persist and picker implementation for every optional segment.
- Unknown future keys in workspace `statusLine` objects stay preserved.

### Negative

- `StatuslineItem`, catalog ids, and command switches grow two more cases.

### Risks

- Legacy workspace `statusLine` cleanup must include the new keys. Mitigation: extend the existing nested-leaf cleanup switch.

## Implementation Notes

Malformed `statusLine.cwd` or `statusLine.branch` values fail with typed parse errors, matching sandbox/context/session.

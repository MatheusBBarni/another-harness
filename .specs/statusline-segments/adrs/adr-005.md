# ADR-005: Refresh Identity Cache On Workspace Root And HEAD Mtime

## Status

Accepted

## Date

2026-08-20

## Context

Cached labels must not go stale after `/workspace` changes or a branch checkout, and they must not refresh on every paint. Issue 6 says cache until cwd/focus change and never block paint. This process has a stable `workspace_root`; process cwd is not the identity source.

## Decision

Refresh off paint when `workspace_root` changes or the resolved `.git/HEAD` mtime or inode changes. A missing or unreadable HEAD omits branch. Do not poll on a timer, do not hook terminal focus, and do not spawn git.

## Alternatives Considered

### Alternative 1: Workspace root only

- **Description**: Refresh only when `workspace_root` changes.
- **Pros**: Fewest stat calls.
- **Cons**: Branch stays stale after checkout until restart or a workspace change.
- **Why rejected**: Branch checkout is the common update users expect to see.

### Alternative 2: Workspace root plus TTL

- **Description**: Also reread HEAD after a short TTL such as 1s.
- **Pros**: Picks up checkouts even if mtime is unreliable.
- **Cons**: Adds periodic I/O to an otherwise event-driven footer.
- **Why rejected**: HEAD mtime is enough for ordinary checkouts without a poll loop.

## Consequences

### Positive

- Checkout updates the footer without paint-path I/O.
- Non-git workspaces stay a failed HEAD lookup, not an error notice.

### Negative

- Filesystems that do not update HEAD mtime can show a stale branch until workspace_root changes.

### Risks

- Stat-ing HEAD every footer refresh can still be too hot if called from paint. Mitigation: refresh from App lifecycle or workspace-change hooks, then copy borrowed slices into `StatuslineItems`.

## Implementation Notes

Cache key is `workspace_root` plus HEAD path identity (mtime, inode when available). Cwd basename refreshes only when `workspace_root` changes.

# ADR-003: App-Owned Cached Identity Labels

## Status

Accepted

## Date

2026-08-20

## Context

`buildHintLine` already borrows optional strings through `StatuslineItems`. Session title is App-owned (`session_title: std.ArrayList(u8)`). Computing basename or reading HEAD inside paint would put filesystem I/O on every footer frame.

## Decision

App owns `cwd_label` and `branch_label` the same way it owns `session_title`. Refresh those buffers off paint. `buildHintLine` and `RenderContext.statusline` stay borrow-only.

## Alternatives Considered

### Alternative 1: Paint-time computation

- **Description**: Derive basename and a cached HEAD read inside the footer assembler each paint.
- **Pros**: No extra App fields beyond toggle flags.
- **Cons**: Puts path and filesystem work on the paint path, or hides a cache in UI code.
- **Why rejected**: UI must not own product state, and paint must not do git I/O.

### Alternative 2: Shared workspace helper used at paint time

- **Description**: Extract an identity helper and call it from the footer assembler.
- **Pros**: Easier unit testing of parse helpers.
- **Cons**: Still risks paint-path I/O unless App caches the result.
- **Why rejected**: A helper is optional later; ownership still has to live on App.

## Consequences

### Positive

- Matches existing session-title ownership.
- Keeps `src/ui/render.zig` free of workspace and git I/O.

### Negative

- App grows two more owned buffers and a refresh hook.

### Risks

- Stale labels if refresh is skipped after a workspace change. Mitigation: ADR-005 invalidates on workspace root and HEAD mtime.

## Implementation Notes

`StatuslineItems` gains `cwd_label` and `branch_label` optional slices. Empty or null omits the segment. `appendStatusSegment` already drops overflow without a dangling separator.

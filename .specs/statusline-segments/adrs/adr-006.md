# ADR-006: Cover Cwd And Branch Through Existing Test Owners

## Status

Accepted

## Date

2026-08-20

## Context

Hint-line clipping already has Zig tests in `src/ui/render.zig`. Toggle persist and the compact picker already have E2E owners in `tests/e2e/config-persistence.test.ts` and `tests/e2e/tui-slash-menu.test.ts`. A new E2E file would need a `scripts/pgso/corpus.json` classification.

## Decision

Add Zig unit tests for basename, HEAD parse, omit-on-missing, and width clipping. Extend the existing statusline E2E owners for `/statusline cwd|branch`, picker labels, and `statusLine.cwd` / `statusLine.branch` persist. Do not add a new e2e file.

## Alternatives Considered

### Alternative 1: Unit tests only

- **Description**: Cover parse and clipping in Zig and leave tmux owners unchanged.
- **Pros**: Faster local loop.
- **Cons**: Misses persist and picker regressions that those files already own.
- **Why rejected**: The new keys travel the same persist and picker path those tests protect.

### Alternative 2: New dedicated E2E file

- **Description**: Add a new `tests/e2e` owner plus a corpus classification.
- **Pros**: Isolates identity coverage.
- **Cons**: Extra CI shard surface for behavior that already has owners.
- **Why rejected**: Existing files already classify this product path.

## Consequences

### Positive

- No corpus classification change.
- Persist, picker, and paint stay covered where they already live.

### Negative

- Identity rendering in tmux is only asserted as part of broader persist/picker tests.

### Risks

- A narrow footer-only regression could slip if E2E only checks settings JSON. Mitigation: Zig tests own clipping and omit behavior; E2E owns toggle persist and picker labels.

## Implementation Notes

Keep the existing E2E classification. New tests inside those files inherit it.

# ADR-001: One CreditsProvider fetch, two command renderers

## Status

Accepted

## Date

2026-08-20

## Context

`/credits`, `/balance`, and `/xai-usage` currently share `SlashKind.credits`. `/xai-usage` is a silent alias. SuperGrok needs Pi-style `/xai-usage` text while `/credits` keeps a credits-shaped listing. Splitting slash kinds would duplicate the billing fetch and the CLI `CreditsProvider` seam.

## Decision

Keep one `CreditsProvider.fetch` and one `CreditsSnapshot`. Keep `/xai-usage` as a parse-time alias of `/credits`. Thread the invoked token (or a `credits` vs `xai_usage` view) into the handler so `/credits` and `/balance` call `renderCreditsText` and `/xai-usage` calls `renderXaiUsageText`. CLI `fx credits` uses the credits renderer.

## Alternatives Considered

### Alternative 1: Split slash kinds

- **Description**: Give `/xai-usage` its own `SlashKind` and handler.
- **Pros**: Clear dispatch; no payload inspection.
- **Cons**: Two handlers, two tests, and a second CLI surface for the same fetch.
- **Why rejected**: The user chose one fetch and two renderers.

### Alternative 2: Silent alias with one renderer

- **Description**: Leave `/xai-usage` as `/credits` and force Grok data through the existing `[credits]` lines.
- **Pros**: Smallest dispatch change.
- **Cons**: Drops the Pi-style notify text required by the issue.
- **Why rejected**: `/xai-usage` must stop being a silent alias.

## Consequences

### Positive

- One HTTP path for both commands.
- Existing `CreditsProvider` and `fx credits` stay the owner of lookup.

### Negative

- Parse/route must carry the invoked alias, which they do not do today.

### Risks

- Forgetting to thread the alias leaves `/xai-usage` on the credits renderer. Cover this in unit tests.

## Implementation Notes

Change `ParsedCommand.credits` to carry a view. Do not add a new top-level CLI command for `/xai-usage`.

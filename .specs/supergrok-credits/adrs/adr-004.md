# ADR-004: Process-local SuperGrok status-line cache

## Status

Accepted

## Date

2026-08-20

## Context

`grok_billing.renderStatusLineFragment` already formats `SG {n}% · {reset}` and optional `{remaining}/{limit} RPM`. Nothing calls it. `grok_stream.stream` uses `client.fetch` and drops response headers. The footer `StatuslineItems` struct has no SuperGrok slot. Product state must not live only in the live shell.

## Decision

Store the last Grok `CreditsSnapshot` fields and last RPM window on the live `App` as process-owned cache, not in `session.json`. Refresh the billing fields when `/credits` or `/xai-usage` succeeds on an `xai/` model. Update the RPM window from `x-ratelimit-remaining-requests` and `x-ratelimit-limit-requests` after a successful Grok stream. The footer appends `renderStatusLineFragment` only while the selected model is `xai/`.

Do not fetch billing on every paint or at startup. If only RPM is cached, show the RPM segment without inventing a percent. If the model is not `xai/`, omit the SuperGrok fragment.

## Alternatives Considered

### Alternative 1: Fetch on every footer paint

- **Description**: Throttled billing GET during status-line render.
- **Pros**: Percent is always fresh.
- **Cons**: Network on the render path; extra latency and 401 noise.
- **Why rejected**: The user chose a process cache.

### Alternative 2: Persist usage in session.json

- **Description**: Save percent, reset, and RPM across resumes.
- **Pros**: Status line survives restart.
- **Cons**: Hidden product state; stale quota after another client spends it.
- **Why rejected**: Issue asks for last RPM after a Grok response, not durable storage.

## Consequences

### Positive

- Footer stays a renderer. Cache ownership stays in app/runtime.
- RPM can appear after a turn even before the user runs `/credits`.

### Negative

- Percent and reset stay empty until the first successful usage command in this process.

### Risks

- `client.fetch` cannot read headers. The Grok stream must switch to a request that exposes them, without adding a second HTTP stack.

## Implementation Notes

Export `parseRequestWindow` and `renderStatusLineFragment`. The fragment must accept optional billing fields: percent/reset when a usage command has succeeded, RPM when stream headers exist. RPM-only output is `{remaining}/{limit} RPM` with no invented `SG 0%`. Zero secrets in any cached token; cache only counts and billing display fields.

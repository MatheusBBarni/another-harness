# ADR-005: Prove Gateway isolation with injected fetch spies

## Status

Accepted

## Date

2026-08-20

## Context

The bug is that SuperGrok `/credits` still GET `ai-gateway.vercel.sh/coding-agent/v1/credits`. Existing credits tests already inject `FetchGatewayGetResultFn`. A live e2e would need a fake Grok billing server plus a fake Gateway and would be slower than the required proof.

## Decision

Unit-test `fetchCredits` with two injected GET functions: one Gateway, one Grok billing. For selected model `xai/*`, assert the billing URL, SuperGrok headers, and that the Gateway GET is never called. For a non-`xai/` model, assert the existing Gateway path and that billing is never called. Keep the current Gateway credits tests. Assert 401/403 bodies never include the Bearer token.

Do not add a new E2E owner or PGSO corpus entry for this cycle.

## Alternatives Considered

### Alternative 1: TUI/CLI e2e only

- **Description**: Fake both servers in Bun and fail if Gateway is contacted.
- **Pros**: Exercises the real binary.
- **Cons**: Heavier; existing `tui-slash-extra` already covers Gateway denial.
- **Why rejected**: The user chose injected spies.

### Alternative 2: Both unit spies and e2e

- **Description**: Spies plus a new e2e file.
- **Pros**: End-to-end confidence.
- **Cons**: Extra corpus classification and tmux cost for a routing bug.
- **Why rejected**: YAGNI for this cycle.

## Consequences

### Positive

- Fast, deterministic proof that `xai/` never calls Gateway credits.
- Reuses the existing `fetchCreditsWithFetch` test style.

### Negative

- Does not prove the TUI footer fragment on a real TTY.

### Risks

- Spies can pass while the TUI forgets to pass the selected model. Add a focused `commandShowCredits` test that the lookup input includes `app.selected_model`.

## Implementation Notes

Existing `tui-slash-extra` Gateway credits case stays verification for the Vercel path. Live Grok billing remains an intentional network exclusion.
